## Task B1: two-tier classification with precedence

1. Tests first (`node --test test/ego-adapter.test.mjs`): change `stopped-and-length` and `quota-and-length` to expect `conversation_exhausted`; add cases: reworded exhaustion banner "You've reached the maximum length for this conversation. Please start a new chat to continue." → `conversation_exhausted`; reworded quota banner "You have reached your message limit for now. Please try again in 2 hours." → `quota_limited`; an unknown status label next to a matched banner → the matched kind (unknown no longer vetoes); only unknown text → no terminal; `ambiguous-length` ("This conversation is too long." alone, no new-chat token) → still no terminal; hidden, quoted (inside message content), stale-turn and different-response cases keep their expectations.
2. Implementation in the `js` classifier: keep tier 1 (the exact regexes) and add tier 2 on the lower-cased label for `[role=status]`/`[role=alert]` nodes only: `conversation_exhausted` when (`too long` or `maximum length`) and (`new chat` or `start a new`); `quota_limited` when (`message limit` or `usage limit` or `reached your limit`) and `try again`; `provider_error` when `something went wrong` or `error occurred`; `stopped` stays the `Stopped thinking` control (buttons allowed). Replace the `kinds.length !== 1` veto with precedence: drop `unknown` signals, pick the highest of `conversation_exhausted` > `quota_limited` > `provider_error` > `stopped`, return null when nothing matched. The observation's `labels` (sorted unique labels of the matched signals) stay inside the in-page object that feeds `signalDigest`; the returned driver observation still carries no label text.
3. Commit `fix: classify ChatGPT terminal banners by token pairs with precedence`.
