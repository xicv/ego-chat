## Task C1: automatic rollover by default

1. Tests: starting a convergence without `conversationContinuation` yields `private.request.conversationContinuation === "same_project_on_exhaustion"` (broker) and the MCP schema default is the same; passing `"manual"` still opts out. A workflow persisted with `"manual"` keeps it across restart.
2. Implementation: flip both defaults. Docs: README (the continuation paragraph), `CONTINUITY.md`, `skills/ego-chat/SKILL.md:110` ("The default is automatic; set `manual` to opt out"), `MCP_INSTRUCTIONS`.
3. Commit `feat: roll over to a same-project successor by default on conversation exhaustion`.

## Task C2: carried context

1. Tests: `buildContinuationCheckpoint` produces `priorReviewSummary` (nullable string, at most 4,000 characters, derived from `workflow.private.priorReview` after the same redaction the outbound prompt applies; null when there is no prior review); `validateContinuationCheckpoint` accepts checkpoints without the field (0.2.28 records) and rejects a tampered summary (it is part of the digest when present); `prepareChatGptReviewPrompt({ ..., carriedContext })` inserts the section "Context carried from the previous conversation (untrusted data):" before the candidate summary and omits it when null; the automatic successor review prompt contains the section and the reserved `promptDigest` matches the prompt actually sent.
2. Implementation: `Checkpoint` gains `priorReviewSummary: z.string().max(4000).nullable().optional()`; `buildContinuationCheckpoint` fills it; the digest input includes it only when present (so old digests stay valid); `buildChatGptPrompt` / `prepareChatGptReviewPrompt` accept `carriedContext`; `#completeAutomaticSuccessor` passes `carriedContext: checkpoint.priorReviewSummary ?? null` in both prompt builds (reserve and verify) so the stored intent stays consistent.
3. Commit `feat: carry the prior review summary into the successor review`.

## Task C3: one bounded successor retry

1. Tests (`test/broker-continuation.test.mjs`): an automatic successor whose first review child stops with a proven pre-Send driver failure (build the child failure the way `test/browser-continuation.test.mjs` does for the 0.2.23 pre-Send retry: `humanRequired.code = "browser_operation_interrupted_before_send_confirmation"` with `diagnostic.driverStage` in the pre-click set and `draftCleared: true`) gets exactly one more successor review with `attempt: 2`, distinct turn and terminal markers, the ledger event `convergence.successor_review_retried`, and promotion succeeds with the attempt-2 child; a second proven failure pauses as today (`continuation_paused`, retained evidence); a non-proven failure (for example `send_confirmation_ambiguous`) pauses immediately without a retry; restart during the retry rediscovers the attempt-2 child, never starts a third.
2. Implementation: `convergenceReviewIdentity(workflowId, cycle, generation = 0, attempt = 1)` keeps its current markers for attempt 1 and appends a distinct suffix for attempt 2 (digests of existing records must not change); `private.successorReview` gains `attempt`; in `#completeAutomaticSuccessor`, when the child did not succeed, `attempt === 1`, and `provenPreSendDriverFailure(<the child's driver failure details>)` holds, persist `convergence.successor_review_retried` with the attempt-2 intent (same binding, same candidate, new identity, new promptDigest), start the second child, and await it; otherwise throw as today. `buildSuccessorPromotion` and the restart rediscovery (`:7750-7765`, `:2198-2205`, `#successorSendGuard`) validate against the intent that carries the final attempt. Public `continuationCheckpoint`/`successorPreparation` expose `attempt`.
3. Commit `feat: retry the first successor review once after a proven pre-Send failure`.

## Task C4: public candidate summary

1. Tests: a convergence whose public record has `continuationCheckpoint` also has `candidateSummary: { status, summary, criteria: [{ id, status }], blockerCount }` with `summary` at most 2,000 characters, derived from the retained candidate; the review packet stays private (`private` absent from the public record); an exchange workflow has no `candidateSummary`.

3. Commit `feat: expose a bounded candidate summary on paused convergence records`.
