   - webhook configured with a fake `fetchImpl` → a `POST` with `content-type: application/json`, the headers merged, body JSON equal to the alert object; `fetchImpl` rejecting or returning `ok: false` → `{ channel: "webhook", outcome: "failed", error: "webhook_failed" }`;
   - message formatting: `workflowKind`, first 8 characters of `workflowId`, `code`, and `message` truncated to 120 characters; a message containing `"` or newlines is JSON-quoted safely for AppleScript;
   - `record()` appends to `<dataDir>/alerts.jsonl` and keeps at most 200 lines (write 205, read back 200 with the newest last).
2. Implementation: `export function createLocalAlertSink({ dataDir, runner = defaultRunner, fetchImpl = globalThis.fetch, osascript = "/usr/bin/osascript" })` returning `{ describe(), notify(alert), record(receipt) }`. `defaultRunner` wraps `execFile` with `{ timeout: 5_000, maxBuffer: 64 * 1024 }` and resolves `{ code }` (never rejects). Zod schema (strict) as in the spec. `notify` builds `formatAlertMessage(alert)` (exported for tests), runs the macOS channel, then the webhook with `AbortSignal.timeout(5_000)`, returns `{ channels }`, and calls `record({ workflowId, code, channels, at })` itself; `record` uses `fs.promises` append followed by a truncate-to-200-lines rewrite when the file exceeds 200 lines (read, keep the last 200, atomic write with rename). No `console.log`. Export `ALERT_ATTENTION_STATUSES = new Set(["human_required", "failed"])` and `ALERT_ATTENTION_PHASES = new Set(["provider_paused", "capture_paused", "continuation_paused"])` and `isAttentionState(workflow)` for the broker.

   - an exchange that ends `human_required` (use the ambiguous-launch or a driver `humanRequired` fake as the existing `test/store-broker.test.mjs:531-566` and `test/browser-continuation.test.mjs` fixtures do) produces exactly one alert with `kind: "workflow_attention"`, the workflow id and kind, `status: "human_required"`, the `code`, a `message` of at most 200 characters, and an ISO `at`;

In `#transition`, right after the successful `persist` and before the waiter resolution, call `this.#maybeAlert(expected, next)`: `const was = isAttentionState(expected)`, `const now = isAttentionState(next)`, `const code = next.humanRequired?.code ?? next.error?.code ?? null`, `const prior = expected.humanRequired?.code ?? expected.error?.code ?? null`; when `now && (!was || code !== prior)` build the alert `{ kind: "workflow_attention", workflowId, workflowKind: next.kind, bindingKey: next.bindingKey ?? null, status: next.status, phase: next.phase ?? null, code, message: truncate(next.humanRequired?.message ?? next.error?.message ?? The daemon passes `alertSink: createLocalAlertSink({ dataDir: config.dataDir })`.
